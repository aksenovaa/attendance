# Чек-лист новой write/интеграционной задачи (принят из портфельного анализа 20.11.2026)

Перед реализацией любой боевой операции ответить:
- Секреты? → только data/ (gitignore, права 600) или env; никогда в коде/репозитории.
- Целостность? → проверка результата до удаления исходной копии (integrity_check / счётчики).
- Повторяемость? → ledger: что, когда, с какими параметрами, хэш/ответ.
- Необратимость? → dry-run по умолчанию + --confirm; боевые write сначала на тестовой сущности.
- Эмпирика? → константы в конфиг/контекст, зафиксированы тестом, не хардкод в логике.
- Мониторинг? → предупреждение о устаревших данных / отсутствии результата (freshness, watchdog).
- Восстановление? → runbook: как вернуть состояние из бэкапа и ledger.

Применение: каждая новая write-операция (write-back, создание сущностей, экспорт с перезаписью)
проходит чек-лист до коммита; результат фиксируется в 03_STATUS.
